01

Overview

Methexis executes penetration tests at machine speed while leaving the final decision to a human. Everything follows one fixed chain: rules first, approvals second, execution last.

  • Deterministic first — if a deny rule matches, the command never runs.
  • Interruptible — any running task can be paused, taken over by a human, and resumed.
  • Self-hosted — nodes run inside your own network.
  • Auditable — commands, approvals, and rule evaluations are all recorded.
02

Execution model

A task is the smallest scheduling unit. One task runs a lead agent plus at most 64 sub-agents, a node runs at most 10 tasks at once, and every task runs in its own container.

  1. 01

    Create a task

    Define the target scope and authorization boundary, then pick an approval policy.

  2. 02

    Lead agent and sub-agents

    A lead agent coordinates up to 64 sub-agents working in parallel inside the same task.

  3. 03

    Execute in a container

    Each task owns a one-off container that is destroyed when the task ends.

  4. 04

    Record and retest

    Results are written to the task record and can be re-run for retesting.

04

Deny rules

Deny rules are a safety net, not an authorization mechanism. They are evaluated before everything else: a match means the command never reaches approval and never executes.

  • A global baseline applies to every task.
  • Individual tasks can add or remove rules.
  • Evaluation is deterministic — the same input always produces the same result.

Common categories include destructive file operations, reverse shells, credential changes, and persistence. Rule content is fully editable to match your organization's policy.

Deny rules do not replace an authorization scope. Testing must always stay inside the boundary you were authorized to test.

05

Approval policies

Approval decides who lets a command through. Four policies cover the range from fully automatic to fully manual.

PolicyBehavior
OpenCommands run immediately. Suited to low-risk, well-scoped tasks.
HumanEvery command waits for explicit human approval.
AIAn AI reviewer approves or denies each command.
AI with escalationAI reviews first; anything uncertain is escalated to a human.
06

Nodes and deployment

A node is the execution plane. It is deployed wherever you choose — your VPC, your lab, or an isolated network — without depending on platform-managed infrastructure.

  • Delivery: a single binary, or docker-compose.
  • Horizontal scale: add nodes to raise concurrency.
  • Heartbeat: the reporting interval is configurable for restricted networks.
  • Recovery: a disconnected node retries on its own and resumes from where it stopped.
07

Isolation

Isolation works at two levels.

  • Task level: one container per task, destroyed when the task ends.
  • Tenant level: data, nodes, and models are fully isolated between tenants, with no shared state.

That serves internal security teams and security vendors delivering for multiple clients from one platform.

08

Audit and takeover

Any running task can be paused, taken over by a human, and resumed. Every step is written to the audit record.

  • Commands, approval decisions, and rule evaluations are all recorded.
  • Tasks can be paused, taken over, and resumed.
  • Results can be re-run and retested.
09

FAQ

  1. 01

    Where can a node run?

    Anywhere you control: your VPC, a lab network, or an isolated segment. No platform-managed infrastructure is required.

  2. 02

    How much does one node handle?

    10 concurrent tasks, each with one lead agent plus up to 64 sub-agents.

  3. 03

    Can Methexis bypass my rules?

    No. Rules run before approval and execution; a match means the command never runs.

  4. 04

    Is multi-tenant delivery supported?

    Yes. Data, nodes, and models are isolated per tenant.

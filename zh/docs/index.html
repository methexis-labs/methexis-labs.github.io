使用文档

Methexis 如何执行一次测试：先过确定性规则，再走可配置审批，最后在一次性容器中执行。

适用于即将发布的 open-source 版本。

01

概述

Methexis 以机器速度执行渗透测试，同时把最终决定权留给人。整个系统遵循一条固定链路：先规则，再审批，最后执行。

  • 确定性优先——命中拦截规则，命令就不会执行。
  • 随时可接管——任何进行中的任务都可以暂停、由人接管、再恢复。
  • 自托管——节点运行在你自己的网络中。
  • 可审计——命令、审批与规则评估全部留痕。
02

运行模型

任务是调度的最小单位。一个任务由 1 个主 Agent 调度最多 64 个子 Agent，一个节点最多同时运行 10 个任务，每个任务运行在自己的容器中。

  1. 01

    创建任务

    定义目标范围与授权边界，然后选择审批策略。

  2. 02

    主 Agent 与子 Agent

    主 Agent 在同一任务内调度最多 64 个子 Agent 并行工作。

  3. 03

    容器内执行

    每个任务拥有独立的一次性容器，任务结束时销毁。

  4. 04

    记录与复测

    结果写入任务记录，可复跑用于复测。

03

控制链路

每条命令都要依次通过三层，任何一层都可以将它终止。

层作用结果
拦截规则代码级确定性检查，先于一切评估命中即拒绝
审批四级策略决定由谁授权通过、拒绝或升级
执行在一次性容器中运行隔离并留痕
04

拦截规则

拦截规则是安全网，不是授权机制。它先于一切评估执行：命中即拒绝，命令既不会进入审批，也不会被执行。

  • 全局基线适用于每个任务。
  • 单个任务可以增加或移除规则。
  • 评估是确定性的——同样的输入永远得到同样的结果。

常见类别包括破坏性文件操作、反弹 Shell、凭据修改与持久化。规则内容完全可编辑，以匹配组织策略。

拦截规则不替代授权范围。测试必须始终停留在你被授权测试的边界内。

05

审批策略

审批决定一条命令由谁放行。四条策略覆盖从全自动到全人工的区间。

策略行为
免审批命令立即执行。适用于低风险、范围明确的任务。
人工审批每条命令都等待人工明确批准。
AI 审批由 AI 审查员逐条批准或拒绝。
AI 审批 · 不确定转人工AI 先审，任何不确定的命令升级给人工。
06

节点与部署

节点是执行平面。它部署在你指定的任何位置——你的 VPC、实验室或隔离网络——不依赖平台代管的基础设施。

  • 交付形式：单文件二进制，或 docker-compose。
  • 横向扩展：增加节点即可提升并发能力。
  • 心跳：回传间隔可配置，适配受限网络。
  • 恢复：断连节点自动重试，并从中断处继续任务。
07

隔离

隔离分为两层。

  • 任务级：每个任务一个容器，任务结束即销毁。
  • 租户级：数据、节点与模型在租户之间完全隔离，无任何共享状态。

这既服务企业内部安全团队，也服务在一个平台上交付多客户的安全厂商。

08

审计与接管

任何进行中的任务都可以随时暂停、由人工接管、再恢复执行。每一步操作都会写入审计记录。

  • 命令、审批结果与规则评估全部留痕。
  • 任务可暂停、接管、恢复。
  • 结果可复跑、可复测。
09

常见问题

  1. 01

    节点可以部署在哪里？

    任何你控制的环境：你的 VPC、实验室网络或隔离网段，无需平台代管基础设施。

  2. 02

    一个节点能跑多少？

    10 个并发任务，每个任务 1 个主 Agent + 最多 64 个子 Agent。

  3. 03

    Methexis 会绕过我的规则吗？

    不会。规则先于审批与执行，命中即拒绝，命令不会运行。

  4. 04

    支持多租户交付吗？

    支持。数据、节点与模型按租户完全隔离。
